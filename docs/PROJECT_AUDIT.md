## 3. Архитектура

### 3.1 Путь запроса

```
index.html (fetch через api(), index.html:606)
  -> /api/v1/biometrics/{modality}/process|compare|evaluate|relief|detectors|embedders|embedders/eval|upload
     app/api/v1/biometrics.py
       _mod(): registry.get_module() (404 при неизвестной модальности), biometrics.py:29-33
       _guard(): ValidationError -> 422, KeyError -> 404, ValueError -> 400, biometrics.py:36-44
       NotImplementedError -> 501 в каждом маршруте отдельно
     -> app/modules/<modality>/module.py (FingerprintModule / FaceModule / IrisModule)
          params: dict -> Pydantic-модель params.py (границы совпадают с ползунками)
          _run(sample_id, params): LRU-кэш OrderedDict -> pipeline -> результат
```

### 3.3 Реестр обученных сетей (`app/training/registry.py`)

- `store()` кладёт сеть в `_cache` и пишет `data/trained/<modality>.npz` (`registry.py:54-60`). Каталог берётся как `Path(settings.db_path).resolve().parent / "trained"`.
- `get()` читает файл через `np.load(..., allow_pickle=False)`, при любой ошибке возвращает `None` (`registry.py:63-78`).
- `embed()` держит общий `_lock` на время `forward` (`registry.py:97-98`).
- Потребители: `fingerprint/matchers.py:30-34, 178-187`, `iris/module.py:192-195, 272-286`, `face/embed.py:33-34, 45-46`, `face/module.py:247-249`.
- Одна сеть на модальность на весь экземпляр сервера. Следующий запуск обучения перезаписывает предыдущую (`trainer.py:183-187`).

### 3.4 БД и события

- `app/core/db.py:37-46`: на каждый вызов открывается новое `sqlite3`-соединение (`connect()`), коммит в конце.
- Схема (`db.py:9-34`): `experiments`, `attempts`, `events`, `training_runs`. Никакой таблицы пользователей и ни одного поля `user_id`.
- События пишет `services/events.record_event` из роутеров: `upload`, `process`, `compare`, `evaluate`, `relief3d`, `embedders_eval`, `code_run`, `code_submit`, `hint`, `train_start`, `tutor`. Факты по `lab.db`: 11 типов, 248 записей.
- Путь `DB_PATH=data/lab.db` относительный (`config.py:8`). Работать с ним будет та папка, из которой запущен сервер.

### 3.5 Практикум

`api/v1/code.py` -> `sandbox/executor.execute()` (длина ≤ 20 000, `check_code`, подпроцесс `python -I -X utf8 runner.py`, `executor.py:46`) -> `runner.py` (exec в урезанных builtins, тесты basic + edge, `@@RESULT@@` в stdout) -> `services/grader.grade()` -> `services/attempts.add_attempt()`. ### 3.6 Обучение

`api/v1/training.py` -> `trainer.start()` -> поток `_run` -> снимок на эпоху `_snap` -> `_finish` (`registry.store` + `training_runs.save`). Снимки лежат в памяти процесса (`Trainer.snapshots`).

## 7. Риски и баги по важности

Порядок: от самых серьёзных.

### Высокие

**H1. Песочница обходится разрешёнными модулями** (`app/sandbox/safety.py:8-15, 38-42`).
- `ALLOWED_IMPORTS` разрешает `cv2`, `statistics`, `operator`, `skimage`. Проверка атрибутов блокирует только перечисленные имена (`BANNED_ATTRS`) и всё, что начинается с `__`.
- Проверено командой `hasattr`: у `cv2` есть атрибуты `os`, `sys`, `importlib`; у `statistics` — `sys`.
- Проверено `check_code()` (статически): **не блокируются** `cv2.os.listdir`, `statistics.sys.modules`, `operator.attrgetter`, `skimage.io.imsave`, `cv2.FileStorage`.
- `operator.attrgetter` позволяет получить атрибут по строке, которую собрали конкатенацией, и обойти запрет на `getattr` и на строки с `__`.
- Что открыто (по коду, **не воспроизводил**): чтение файлов проекта — решения заданий в `app/tasks/*.json`, `.env` с `OPENAI_API_KEY`, `data/lab.db`; запись файлов; сеть (она не заблокирована вообще); доступ к `sys.modules` процесса-раннера, где загружены эталоны `app.sandbox.reference`.
- Переменные окружения родителя подпроцессу не передаются (`executor.py:39-40`), это снижает риск утечки ключа из окружения, но не из файла `.env`.
- Тест `tests/test_code_lab.py:41-54` проверяет только семь заведомо заблокированных шаблонов; обходов в нём нет.
- Последствие: защита «решения не должны уходить на клиент» держится только на честности студента. Для защиты диплома нужно честно говорить «учебная защита» (так и написано в `safety.py:3-4` и README:159-161), либо закрыть дыры (план, шаг 2).

**H2. Тест портит офлайн-библиотеку** (`tests/test_web_assets.py:10-24`).
- Тест пишет `//test` в `app/web/vendor/plotly.min.js` и удаляет файл только если его не было (`had`). Если вы выполнили `python -m scripts.download_assets`, то после `pytest` настоящий Plotly заменён строкой `//test`, и графики пропадут при следующем запуске.
- Сейчас папки `app/web/vendor` нет (`ls app/web`), поэтому у вас это не проявилось. **Не воспроизводил**, вывод по коду.

**H3. Git-гигиена** (раздел 5, п. 1–3). Две вещи вместе опасны: одна команда `git add .` закоммитит 146 МБ чужих лиц и 62 МБ моделей, и это же единственная точка сохранения. Добавьте правила в `.gitignore` до первого коммита.

### Средние

**M1. Кэши без блокировок** (`fingerprint/module.py:77-86`, `face/module.py:176-185`, `iris/module.py:141-150`).
FastAPI выполняет синхронные обработчики в пуле потоков, фронтенд шлёт запросы параллельно. Последовательность «`in cache` -> `move_to_end` -> `popitem`» над `OrderedDict` без `Lock` может дать `KeyError` при гонке (запись вытеснена между проверкой и `move_to_end`). Воспроизводить не пытался. Без нагрузки проявляется редко, но это источник «плавающих» 500.

**M2. Память кэшей считается штуками, а не байтами.** В записях лежат изображения этапов. Оценка (не измерял): результат лица с картинками занимает порядка нескольких МБ (кадр до 640 px × 3 канала × несколько копий), 300 записей дадут порядка 1 ГБ. Для отпечатков 400 записей по ~1 МБ — до 0,4 ГБ.

**M3. Галерея LFW делает вкладку «Лицо» медленной** (замер на этой машине).
- `FaceModule._scan()` — 0,99 с на 5 749 человек; `list_samples()` — 0,94 с и 13 233 элемента (≈1,6 МБ); `info()` — 0,88 с.
- Эти вызовы повторяются при каждом открытии вкладки (`index.html:1157` `loadSamples()`, `loadInfo()`), в `_gallery_mean`, `_eigen`, `evaluate`.
- Выпадающий список из 13 233 пунктов в браузере (не проверял).

**M4. Обучение на лицах перебирает всю галерею** (`training/datasets.py:64-71`). Цикл `for person, lst in m._scan().items()` прогоняет полный конвейер лица (детекция и выравнивание) по первым 8 фото **каждого** из 5 749 человек, и только потом берёт первые 12 (`datasets.py:72`). Это до 13 233 прогонов конвейера (все файлы галереи) вместо ≈ 100 для 12 человек (оценка по коду; время не измерял, но детекция занимает десятки миллисекунд, README:89). Единственный тест на `load_face` проверяет лишь пустую галерею (`tests/test_training.py:73-76`).

**M5. Нет таймаута на отдельный тест на Windows** (`sandbox/runner.py:49-59`). Таймаут по 3 с на тест использует `signal.setitimer`, на Windows его нет. Бесконечный цикл блокирует слот на все 20 с `executor.py:29` и обнуляет оценку. Слотов всего два (`executor.py:14`), так что несколько таких запусков подряд блокируют вкладку практикума для всех. Памяти ограничений нет.

**M6. Счётчик попыток глобальный и накручивается** (`api/v1/code.py:63-74, 80`, `code_tutor.py:69-74`).
- Любая отправка, даже пустая, синтаксически неверная или заблокированная песочницей, увеличивает счётчик и после трёх открывает полное решение.
- Баллы за контрольный вопрос (1 из 10) можно получить перебором четырёх вариантов: число отправок не ограничено (в `grader.py:11` нет учёта предыдущих ответов).
- Так как пользователей нет, счётчик общий для всех, кто открыл сервер.

**M7. Наставник OpenAI** (`services/tutor.py:174-177, 193-199`).
- `get_tutor()` создаёт `OpenAITutor()` без `try`. Если пакет `openai` не установлен (он закомментирован в `requirements.txt:13`), `/api/v1/tutor/ask` вернёт 500 и так и будет, пока не поправят `.env`. README обещает «возврат к правилам» только при ошибке API, не при отсутствии пакета.
- `except Exception` на `tutor.py:186-187` глотает любые ошибки молча, без лога.
- Запрет «не давай готового решения» только в системном промпте (`tutor.py:170-172`), не проверяется кодом.
- LLM-наставник вообще не подключён к практикуму: `services/code_tutor.py` использует только правила (его docstring прямо говорит, что LLM можно подключить позже).
- Автотестов на `OpenAITutor` нет.

**M8. Загрузка файлов** (`api/v1/biometrics.py:68-75`).
`await file.read()` читает файл целиком **до** проверки размера: лимит 5 МБ не защищает память. Нет лимита на число пикселей: сжатый PNG на 5 МБ может декодироваться в сотни мегабайт (`cv2.imdecode`). Загрузки общие для всех посетителей сервера (`_uploads` в модуле, без пользователя).

**M9. Зависимости** (`requirements.txt`).
- `opencv-python>=4.9` без верхней границы. CLAUDE.md требует `<5`, потому что в 5.x нет `cv2.CascadeClassifier`. Новая установка с чистого листа может поставить 5.x и сломать детекторы Хаара.
- `scipy` напрямую импортируется (`iris/localize.py:11`, `fingerprint/filters.py:5`), но не указан; приходит транзитивно через `scikit-image`. То же для `pydantic`.
- `scikit-learn` нужен только скрипту `prepare_lfw.py:124`.
- Окружение сейчас рабочее: fastapi 0.143.0, numpy 2.5.3, opencv-python 4.11.0.86, scikit-image 0.26.0, scipy 1.18.1, pydantic 2.14.0 (`pip list`). Lock-файла нет. Проверка `pip check` не выполнялась.

**M10. Дублирование метрик** (раздел 6). Исправление ошибки в одной копии не попадёт в остальные.

### Низкие

- **L1. Путь БД и сетей зависит от текущей папки** (`config.py:8`, `db.py:39`, `registry.py:50-51`). Запуск `uvicorn` из другой папки создаст вторую `data/lab.db` и скроет обученные сети. Модели и галерея привязаны к `__file__` (`face/models.py:19`, `face/module.py:24`), то есть ведут себя иначе.
