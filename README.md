# Виртуальная лаборатория «Биометрия»

Учебная веб-лаборатория по курсу «Биометрия»: студент видит весь путь от изображения до решения
(**изображение → предобработка → признаки → шаблон → сравнение → порог → MATCH / NO MATCH**), меняет параметры,
сравнивает разные методы на одних и тех же данных и анализирует качество (FAR, FRR, EER).

Вкладки: **Отпечатки пальцев**, **Лицо**, **Радужка**, **Голос**, **Практикум: код**, **Обучение распознаванию**, **Площадка нейросети**.
Реальные биометрические данные людей в лаборатории не используются: отпечатки и глаза синтетические, лица берутся из открытых
наборов (например LFW) или из фото с согласия людей.

## Запуск в PyCharm

1. Откройте папку проекта (`File → Open`), создайте интерпретатор Python 3.11-3.13 (Virtualenv в `.venv`).
2. В терминале PyCharm (в начале строки должна быть приписка `(.venv)`):
   ```
   python -m pip install -r requirements.txt
   python -m scripts.download_models        # нейросетевые модели лица, по желанию (около 40 МБ)
   python -m scripts.download_assets        # Plotly и Three.js локально: лаборатория работает без интернета (кроме редактора кода), по желанию
   python -m uvicorn app.main:app --reload
   ```
3. Откройте http://127.0.0.1:8000 (документация API: http://127.0.0.1:8000/docs), после обновления нажмите `Ctrl+F5`.

Тесты: `python -m pytest -q`. Тесты работают на временной базе и не трогают вашу `data/lab.db`; тесты, которым нужны скачанные
модели, пропускаются, пока моделей нет.

## Что внутри вкладок

### Отпечатки пальцев
- **8 этапов** с картинкой и пояснением: grayscale → сегментация → нормализация (CLAHE) → поле ориентаций → фильтр Габора →
  бинаризация → скелетизация → minutiae (● окончание, ▲ разветвление). Все параметры меняются ползунками.
- **Бинаризация (3 метода):** адаптивный порог, метод Оцу, фиксированный порог. Оцу рвёт гребни и даёт много ложных окончаний.
- **Сопоставление (5 методов):** минуции + голосование за поворот и сдвиг (основной), минуции + локальные структуры соседей,
  фазовая корреляция POC, ключевые точки SIFT, нейросеть, обученная вами. У каждого метода своя шкала сходства и рекомендуемый порог (подставляется сам).
- Сравнение двух образцов, порог, график FAR/FRR/EER, журнал экспериментов с выгрузкой в CSV, 3D-рельеф гребней,
  3D-конвейер этапов (ползунки поворота 0-360°, наклона, приближения, облёт, раскладки «лента», «стопка», «карусель»).

### Лицо
- **Детекторы (7):** четыре каскада Хаара (frontalface_default, alt2, alt, профиль), нейросети SSD ResNet-10, UltraFace RFB-320, YuNet.
- **Признаки (9):** нейросети SFace и ArcFace MobileFaceNet; классика: LBP, HOG, Габор, DCT, нормированные пиксели, Eigenfaces (PCA по галерее).
- 6 этапов: детекция → ключевые точки → выравнивание → нормализация освещения → embedding → сравнение (косинусное сходство).
- Классические признаки у всех лиц похожи, поэтому из них вычитается «среднее лицо» галереи (нужно 3+ человека).
- Галерея: `datasets/faces/<имя_человека>/*.jpg`; подготовка набора LFW: `python -m scripts.prepare_lfw`.

### Радужка
- **8 этапов:** снимок → предобработка → зрачок → граница радужки → сегментация (маска век, ресниц, бликов) →
  нормализация Даугмана «резиновый лист» (32×256) → фильтры → Iris Code → сравнение по расстоянию Хэмминга с перебором сдвигов
  (компенсация поворота глаза). Сходство = 1 − HD.
- **Локализация (3 метода):** интегро-дифференциальный оператор Даугмана, преобразование Хафа, порог + радиальный поиск границы.
- **Кодировщики (6):** 2D-фильтры Габора (Даугман), 1D лог-Габор (Masek), порядковые признаки (ordinal), DCT (Monro), вейвлет Хаара,
  нейросеть, обученная вами.
- Датасет синтетический: 12 глаз × 3 снимка с веками, ресницами, бликами, разным зрачком и поворотом. Генератор знает истинные
  окружности, поэтому на вкладке видна **ошибка локализации** относительно эталона.

### Голос
Распознавание **диктора** (кто говорит, а не что сказано) на тех же принципах, что и остальные биометрии: этапы, сравнение, порог, FAR/FRR/EER, сравнение методов.
- **7 этапов** с картинкой и пояснением: исходный сигнал → выделение речи (VAD) → спектрограмма → мел-спектрограмма → MFCC → высота тона (f0) → шаблон голоса.
- **Выделение речи (3 способа):** адаптивный порог по энергии, фиксированный порог (дБ ниже пика, ползунок), энергия + пересечения нуля (без шума).
- **Методы шаблона (4):** MFCC (средние и разброс, тембр), MFCC + динамика (дельта-коэффициенты), только высота тона, MFCC + высота тона. Сходство = exp(-d²), где d² - средний
  квадрат разности z-оценок шаблонов; у методов разные шкалы и пороги (подставляются сами). На синтетических дикторах EER: MFCC около 5 %, MFCC + динамика 6 %, MFCC + высота 8 %, только высота около 25 %.
- **Данные:** 12 синтетических дикторов по 3 записи (`app/modules/voice/synthetic.py`: импульсы гортани через резонаторы речевого тракта, у каждого диктора свои высота тона и длина тракта),
  все говорят одну и ту же фразу, чтобы сравнивался голос, а не содержание. Реальных записей людей в лаборатории нет.
- **Свой голос:** кнопки «Записать в A / в B» (микрофон, 4 секунды; нужен `localhost` или HTTPS) и «Загрузить» (WAV, MP3 и др.: браузер приводит звук к WAV 16 кГц). Кнопки «▶ A» и «▶ B» проигрывают записи.
  Записи хранятся только в памяти сервера и видны только вам (как загрузки изображений). Шаблоны приводятся к z-оценкам по синтетическим дикторам, поэтому для настоящих голосов
  качество ограничено: это учебная модель, а не промышленное распознавание диктора.
- Ползунок шума и число коэффициентов MFCC позволяют проверить, как помехи и размер шаблона влияют на результат. Голосом можно сказать: «открой голос и сравни записи», «запиши мой голос в образец А», «прослушай образец Б».
- Отдельное дополнение **LAB+** (страницы `/labplus/voice` и др.) осталось: регистрация голосового профиля, ROC и DET, устойчивость.

### Сравнение методов (карточка на вкладках отпечатков, лица, радужки и голоса)
Три кнопки: сравнить способы получения признаков на одном образце (бинаризации, детекторы, локализаторы), сравнить методы
сопоставления на одной паре, оценить методы по **EER на всём наборе** (лучший отмечается, показан запас «худший свой минус лучший чужой»).
Числа сходства разных методов напрямую сравнивать нельзя: судить о методе нужно по EER и запасу.

### Практикум: код
5 заданий с редактором (Monaco), безопасным запуском, оценкой по рубрике (10 баллов), разбором ошибок, 4 уровнями подсказок и
контрольным вопросом. Полное решение открывается после 3 попыток. Запуск идёт в отдельном процессе с проверкой кода (AST),
ограничением времени и ресурсов (на Windows только время). Это учебная защита, не промышленная.

### Обучение распознаванию
Маленькая свёрточная сеть (NumPy, без PyTorch) учится различать пальцы, лица или глаза: кривые Loss, точности и EER, схема сети,
карты признаков, изменение весов по слоям, embedding на плоскости, гистограмма «свои / чужие», проверка на новых образцах.
- **Настройки:** размер сети (малая 8-16-16, средняя 12-24-24, большая 16-32-32 фильтров), оптимизатор (Adam или SGD с моментом;
  для SGD нужен шаг около 0,005-0,01), какой снимок оставить для проверки, learning rate, батч, число эпох, аугментация.
- **Готовые эксперименты (7 кнопок):** базовый запуск, без аугментации (переобучение), слишком большой шаг (сеть не учится),
  слишком малый шаг, большая сеть, SGD вместо Adam, проверка на лёгком снимке. Каждый запускается одним кликом.
- **Итоги и выводы:** после обучения лаборатория сама объясняет результат (переобучение, не обучилась, недообучена, высокий EER).
- **Журнал запусков:** все запуски хранятся в базе; отметьте несколько и нажмите «Сравнить выбранные» (кривые Loss и точности), CSV для отчёта.
- **Сеть как метод распознавания:** обученная сеть сохраняется в `data/trained/` и выбирается в списках методов на вкладках отпечатков,
  радужки и лица («Нейросеть, обученная вами»). Порог подставляется сам (по EER на снимках, которых сеть не видела). EER для отпечатков и
  радужки считается только по парам со снимком, оставленным для проверки; для лиц галерея входила в обучение, поэтому оценка завышена.

### Площадка нейросети
Многослойный перцептрон в браузере: данные (в том числе «биометрия: свой / чужой»), слои, нейроны, learning rate, граница решения.

## Измеренные характеристики методов

Измерено на синтетических данных лаборатории; на реальных данных все ошибки будут выше, а порядок методов может измениться.

| Область | Метод | Результат |
| --- | --- | --- |
| Отпечатки, сопоставление | голосование / локальные структуры / POC | EER 0 %; SIFT: EER около 13 % |
| Отпечатки, бинаризация | Оцу | около 80 % минуций - ложные окончания |
| Радужка, локализация | Даугман / контур / Хаф | ошибка 1,1 / 0,4 / 5,1 px по радужке; Хаф не нашёл радужку на 1 снимке из 36 |
| Радужка, кодировщики | Габор, ordinal, лог-Габор, DCT, Хаар | запас +0,15 / +0,12 / +0,07 / +0,06 / отрицательный (EER 16 %) |
| Лицо, детекторы | UltraFace / SSD / Haar | около 50 / 130 / 150 мс на кадр |
| Лицо, признаки | ArcFace | один человек около 0,95-0,98, разные около 0 |

## Удобство и скорость

- Над результатами показана цепочка шагов «выберите, покажите этапы, сравните, оцените» с подсказкой, что делать дальше; кнопка «Как работать» открывает короткую инструкцию по текущей вкладке.
- Миниатюры выбранных образцов A и B; редкие параметры спрятаны в «Дополнительные параметры»; под каждым списком метода есть пояснение.
- Вкладка и параметры запоминаются в браузере; ошибки показываются уведомлениями.
- Скорость: фильтр Габора считается через FFT (конвейер отпечатка около 25 мс вместо 210 мс), обучение сети быстрее примерно на 40 %,
  ответы API сжимаются, Plotly и Three.js не блокируют показ страницы.

## Данные

- `datasets/synthetic/` - 12 пальцев × 3 оттиска (`python -m scripts.generate_dataset`).
- `datasets/synthetic_iris/` - 12 глаз × 3 снимка и `truth.json` с истинными окружностями (`python -m scripts.generate_iris_dataset`).
- `datasets/faces/` - ваша галерея лиц (папки по людям); в репозиторий не попадает.

### Реальные открытые наборы данных

Это биометрические данные настоящих людей, поэтому они лежат отдельно от синтетики, не попадают в репозиторий (`.gitignore`) и подходят только
для учебных и исследовательских целей: не распространяйте файлы и цитируйте авторов наборов. Метрики на реальных данных хуже, чем на синтетике:
это ожидаемо, и именно это стоит показывать студентам.

**Как это выглядит в лаборатории.** На вкладках «Отпечатки пальцев», «Радужка» и «Лицо» в карточке «1. Образцы» есть список **«Набор данных»**
и поиск по образцам (в наборах тысячи образцов, показываются первые 500 подходящих). Наборы, которых нет на диске, в списке не появляются.
Реальные наборы помечены «реальные данные», эта же пометка стоит рядом с результатом оценки FAR/FRR/EER. Набор запоминается в браузере.
В списке SOCOFing после каждого оригинала идут его искажённые копии: выберите оригинал в A и копию в B, чтобы получить «свою» пару (два оригинала
разных пальцев - «чужая»).
На вкладке «Обучение распознаванию» рядом с «Что распознаём» есть список «Набор данных»: сеть можно обучить на синтетике или на реальных
снимках. Сеть запоминает, на каком наборе обучена, и на другом наборе не применяется: вместо неверного результата показывается понятное сообщение.
Список «Объектов» зависит от набора: синтетика 12, FVC 10 пальцев, CASIA до 40 глаз, лица до 30 человек (больше объектов - дольше обучение).
EER в заголовке эпохи считается по проверочным снимкам против обучающих (сеть их не видела). У реальных наборов «снимок для проверки» - просто номер
снимка по порядку; «самый лёгкий» и «самый сложный» бывают только у синтетики. Сеть учится различать только выбранные объекты, незнакомых не узнаёт.

| Набор | Где лежит | Что даёт в лаборатории |
| --- | --- | --- |
| FVC2002 и FVC2004, набор «B», базы DB1-DB4 | `datasets/real/fvc2002/DB1..DB4/`, `datasets/real/fvc2004/DB1..DB4/` (файлы `<палец>_<оттиск>.tif`) | отпечатки: сравнение, этапы, EER по 10 пальцам × 8 независимым оттискам, обучение сети |
| SOCOFing | `datasets/real/socofing/Real/` и `Altered/Altered-Easy, -Medium, -Hard/` | отпечатки: сравнение и этапы; **EER не считается** (по одному снимку на палец: «свои» пары были бы оригиналом и его искажённой копией); вместо него карточка «Стресс-тест искажений» |
| CASIA-Iris-Interval | `datasets/real/casia_iris_interval/<человек>/<L или R>/S1001L01.jpg` | радужка: сравнение, этапы, EER по глазам с 3+ снимками, обучение сети; истинных окружностей в наборе нет, ошибка локализации в пикселях не показывается |
| LFW | `datasets/faces/LFW/<человек>/<фото>.jpg` (либо `datasets/faces/<человек>/<фото>.jpg`) | лицо: набор «LFW» или «все источники»; можно держать несколько папок-источников рядом |

Образцы называются так: `fvc2004:DB1:101_3` (палец 101, оттиск 3), `soco:100__M:Left_index` (оригинал) и `soco:100__M:Left_index:Hard:Obl`
(искажённая копия), `casia:S1001L01` (человек 001, левый глаз, снимок 1), `LFW::Aaron_Eckhart__Aaron_Eckhart_0001`.
Кадры FVC вырезаются по центру в масштабе 1:1 (чтобы не менять период гребней), SOCOFing увеличивается в 2 раза.
**Пороги на реальных наборах.** Методы сопоставления у каждого свою шкалу сходства, а пороги по умолчанию подобраны под синтетику (0,5 и т. п.).
Поэтому при выборе реального набора порог подставляется свой: он замерен как «порог при EER» на самом наборе (таблица в `app/modules/fingerprint/real.py`,
`THRESHOLDS`; для радужки в `app/modules/iris/real.py`). Например, у метода «голосование» на FVC это около 0,19-0,24 вместо 0,5.
Замер при настройках по умолчанию (FVC набор B, 10 пальцев × 8 оттисков; радужка: первые 12 глаз × 3 снимка CASIA):

| Набор | голосование | локальные структуры | POC | SIFT |
| --- | --- | --- | --- | --- |
| FVC2004 DB1 / DB2 / DB3 / DB4 | 28 / 40 / 19 / 23 % | 40 / 49 / 24 / 40 % | 35 / 34 / 22 / 26 % | 41 / 34 / 18 / 52 % |
| FVC2002 DB1 / DB2 / DB3 / DB4 | 23 / 34 / 28 / 20 % | 31 / 41 / 32 / 34 % | 27 / 39 / 13 / 23 % | 24 / 18 / 40 / 53 % |

(EER при настройках по умолчанию.) Радужка CASIA: Габор 16,7 %, ordinal 19,2 %,
вейвлет Хаара 18,8 %, лог-Габор 20,0 %, DCT 36,2 %. Это EER при **параметрах по умолчанию, настроенных на синтетику**: подбор параметров конвейера
(период и сигма Габора, сглаживание, допуски сопоставления) под реальные снимки может заметно его снизить; в лаборатории такой подбор не выполнялся.

**Как подготовить данные**

FVC2002 и FVC2004 набор «B» скачиваются со страниц [FVC2004](http://bias.csr.unibo.it/fvc2004/download.asp) и [FVC2002](http://bias.csr.unibo.it/fvc2002/download.asp)
(архивы `DB1_B.zip` ... `DB4_B.zip`); распакуйте каждый в `datasets/real/fvc2004/DB1/` и т. д.

CASIA и SOCOFing скачайте вручную (нужны аккаунт или запрос), распакуйте и скопируйте одной командой (PowerShell, из папки проекта):

```
python -m scripts.prepare_real --casia "C:\путь\к\casia" --soco "C:\путь\к\soco"
```

Скрипт ничего не скачивает из интернета, исходные папки не меняет, повторный запуск пропускает уже скопированные файлы. Ключ `--soco-people N`
копирует только первых N человек SOCOFing (по умолчанию все 600, около 780 МБ). После копирования перезапустите сервер.

Где взять наборы (регистрация, форма запроса или аккаунт нужны не везде; условия смотрите на страницах):

| Набор | Страница |
| --- | --- |
| CASIA-Iris-Interval (часть CASIA-IrisV4) | [CASIA (CBSR)](http://www.cbsr.ia.ac.cn/english/IrisDatabase.asp); копии есть на Kaggle |
| SOCOFing (6 000 отпечатков, 600 человек) | описание: [arXiv 1807.10609](https://arxiv.org/abs/1807.10609); набор ищите на Kaggle |
| IITD Iris (2 180 снимков, 218 человек, 320×240) | [страница базы](https://www4.comp.polyu.edu.hk/~csajaykr/IITD/Database_Iris.htm): форма запроса, коммерческое использование запрещено, цитировать Kumar и Passi (Pattern Recognition, 2010). Пока не подключён |
| PolyU, бесконтактные отпечатки | [страница базы](https://www4.comp.polyu.edu.hk/~csajaykr/fingerprint.htm): форма запроса. Пока не подключён |
| CelebA | [страница проекта](http://mmlab.ie.cuhk.edu.hk/projects/CelebA.html): только некоммерческие исследования, около 1,4 ГБ; лаборатории не нужен, лица берутся из LFW |

При упоминании результатов ссылайтесь на FVC и на книгу «Handbook of Fingerprint Recognition» (Maltoni и др.).

### Загруженные изображения

Кнопки «в A» и «в B» загружают ваше изображение на сервер для разового просмотра. Оно хранится **только в памяти процесса** (не пишется на диск), видно
только вашему браузеру (анонимная сессия: cookie `lab_sid`, без аккаунтов), у каждого посетителя не больше 20 загрузок, и всё пропадает при перезапуске
сервера. В базе остаётся только служебный идентификатор вида `up_ab12cd`, без изображения. Лимиты: файл до 5 МБ и до 16 мегапикселей.

## Помощник лаборатории

Кнопка 🎤 справа внизу на любой вкладке открывает помощника: он **управляет интерфейсом** по команде голосом (Chrome) или текстом. Например:

- «Покажи, как изображение превращается в решение» - экскурсия: показываются этапы обработки по очереди, каждый озвучивается, затем образцы сравниваются и называется решение MATCH / NO MATCH;
- «Открой радужку, набор CASIA, покажи этапы», «Оцени качество на FVC2004 DB3», «Сравни методом SIFT порог 0,2»;
- «Покажи 3D-конвейер и облёт», «Покажи рельеф», «Сравни методы», «Оцени методы по EER», «Стресс-тест SOCOFing»;
- «Начни обучение на CASIA» (перед запуском спрашивает подтверждение: сохранённая сеть заменяется), «Останови обучение»;
- «Объясни результат» (разбор последнего сравнения наставником), «Что ты умеешь».

**Новые возможности голосового управления.**
- Числа словами: «порог ноль пять», «порог пятьдесят процентов», «палец сто один оттиск три», «этап четыре». «Увеличь порог» и «уменьши порог на 0,1» меняют порог относительно текущего.
- Выбор образцов: «выбери палец сто три оттиск два как образец Б», «сравни палец 101 оттиск 1 и палец 102 оттиск 1» (по номерам образцов FVC и синтетики).
- Этапы: «следующий этап», «назад», «этап четыре», «последний этап». Практикум: «открой задание бинаризация», «запусти код», «дай подсказку два», «проверь решение»
  (спрашивает подтверждение, потому что попытка засчитывается). Площадка нейросети: «запусти обучение», «шаг», «сбрось».
- «Повтори» повторяет прошлую команду, «стоп» (или Esc) прерывает любую, в том числе экскурсию и озвучку. Alt+V включает микрофон, стрелка вверх в поле ввода листает историю команд.
- Пока вы говорите, в панели виден распознанный текст. Браузер отдаёт до трёх вариантов распознавания, сервер берёт первый, который удалось понять (в журнале помощник пишет «понято как»).
- Если фраза не распознана, помощник предлагает самые близкие команды («возможно, вы имели в виду...»), а не угадывает.

Голосовой ввод работает в Chrome и Edge и на `localhost` или по HTTPS; качество распознавания зависит от браузера и микрофона, текстовый ввод работает везде.

Команда разбирается на сервере по правилам (ключевые слова и шаблоны, `app/services/assistant.py`, `POST /api/v1/assistant/parse`), без внешних сервисов и ключей;
если фраза не распознана, помощник говорит об этом и показывает примеры, а не угадывает. Действия выполняет интерфейс (`index.html`, блок «Помощник лаборатории»),
кнопка «Стоп» прерывает команду. Распознавание речи и озвучку делает браузер: в панели («Озвучка») можно выбрать голос и скорость; самые естественные голоса в Chrome
(«Google русский») и Edge («Microsoft ... Online (Natural)»). Микрофон работает только на `localhost` или по HTTPS.

**Голос лаборатории (Piper).** Озвучку можно поручить серверу: в панели «Озвучка» появляются «Голос лаборатории: Дмитрий» и «Денис». Он одинаков у всех
пользователей, работает без интернета и в любом браузере. Установка (необязательно):

```
python -m pip install -r requirements-tts.txt
python -m scripts.download_tts
```

Второй шаг скачивает два русских голоса по 63 МБ в `models/tts/` (папка вне Git); затем перезапустите сервер. Если голосов нет, помощник говорит голосами браузера.
Лицензии: движок Piper распространяется под GPL-3.0-or-later (ставится отдельным пакетом и в проект не встроен), голоса Дмитрий и Денис обучены на данных CC0
([OHF-Voice/voice-datasets](https://github.com/OHF-Voice/voice-datasets)), репозиторий голосов [rhasspy/piper-voices](https://huggingface.co/rhasspy/piper-voices) помечен MIT.
Первая фраза после запуска сервера звучит с задержкой около 10 секунд (загрузка голоса, она стартует при открытии страницы), дальше синтез быстрый (около 0,4 секунды на 5 секунд речи).
Синтез идёт на процессоре сервера по одной фразе за раз (до 600 символов).

Что помощник пока не умеет: понимать произвольные формулировки (нужны ключевые слова из списка выше), выбирать конкретные образцы A и B по названию, управлять
Практикумом и Площадкой нейросети. Для «умного» режима можно подключить языковую модель с откатом на эти правила (потребуется ключ API).

## Как добавить новую биометрию (например, сетчатку)

1. Создайте `app/modules/<имя>/module.py` с классом `BiometricModule`: `list_samples`, `process`, `compare`, при желании
   `evaluate`, `compare_detectors`, `compare_embedders`, `evaluate_embedders`.
2. Добавьте `register(...)` в `app/modules/registry.py`: маршруты `/api/v1/biometrics/<имя>/...` заработают сразу.
3. В `app/web/index.html` добавьте вкладку и запись в `MODS` (параметры, подсказки в `HINTS`, рекомендуемые пороги методов).

## API (основное)

`GET /api/v1/biometrics`, `/{модальность}/samples|info`, `POST /{модальность}/process|compare|evaluate|upload|relief`,
`POST /{модальность}/detectors|embedders|embedders/eval` (сравнение методов), `/api/v1/code/...` (практикум),
`/api/v1/training/...` (обучение, журнал запусков `/runs`, обученная сеть `/model/{модальность}`), `/api/v1/tutor/ask`, `/api/v1/experiments`. Модальности: `fingerprint`, `face`, `iris`.

## ИИ-наставник

`.env` (по образцу `.env.example`): `TUTOR_PROVIDER=rule` (по умолчанию) или `openai` + `OPENAI_API_KEY` (`pip install openai`).
Режимы: подсказка, объяснение понятия, разбор результата. Наставник на правилах знает термины всех вкладок (минуции, Габор,
HOG, ArcFace, расстояние Хэмминга, rubber sheet, маска век и др.) и разбирает последнее сравнение. При ошибке API он возвращается к правилам.

## Ограничения (честно)

- Метрики посчитаны на синтетике, где разделение «своих» и «чужих» почти идеальное; на реальных данных (FVC, CASIA, LFW) будет хуже.
- Сопоставление отпечатков учебное: поворот до ±40°, ориентации minutiae определены с точностью до 180°.
- Радужка: нет реальных снимков в ближнем ИК-диапазоне; методы локализации настроены на синтетические глаза.
- Модели YuNet и SFace скачиваются отдельно; их характеристики в моей среде не измерялись.
- 3D-рельеф построен по карте высот изображения (псевдо-3D), а не по реальной поверхности.
- Реальные наборы (`datasets/real/`) в репозиторий не входят; их нужно подготовить самостоятельно, см. «Реальные открытые наборы данных».
- Plotly и Three.js подгружаются через CDN (или локально после `python -m scripts.download_assets`), редактор кода Monaco - только через CDN.
- Обучение сети идёт на процессоре: 30 эпох занимают около 20-90 секунд в зависимости от компьютера.
- Защита запуска кода студента учебная; для промышленного использования нужен Docker-контейнер. Проверка кода запрещает доступ к файлам, процессам и сети через
  модули-обёртки (`cv2.os`, `statistics.sys`, `operator.attrgetter`, `skimage.io` и т. п.), но это запрет по именам, а не изоляция: сеть и память не ограничены.
  На Windows таймаут на каждый тест (3 с) обеспечивает сторожевой поток, лимитов памяти нет.

## Ограничения при деплое

Часть состояния лаборатории хранится в памяти процесса или на диске одного экземпляра сервера. Поэтому **запускайте один экземпляр
или включайте привязку сессий к экземпляру (session affinity)**. Достаточно запускать один экземпляр сервера.

| Что | Где хранится | Переживает перезапуск | Что видит студент после перезапуска |
|---|---|---|---|
| Журнал сравнений, попытки практикума, события, журнал запусков обучения | База данных (SQLite или PostgreSQL по `DATABASE_URL`) | да | ничего не меняется |
| Загрузки студента (изображения и записи) | Память процесса, по сессии `lab_sid` | нет | «Загруженный файл не найден… Загрузите файл заново» (ответ 404) |
| Статус обучения и снимки эпох | Память процесса (один `Trainer` на экземпляр) | нет | «Снимок этой эпохи недоступен… Запустите обучение заново» |
| Обученные сети | Файлы рядом с базой (`data/trained`) | только на постоянном диске | «Сеть… ещё не обучена или была потеряна при перезапуске сервера» (ответ 400) |
| Профили голоса и записи фраз LAB+ | Файлы на диске (`labplus_data`) | только на постоянном диске | профиль не найден, создать заново |
| Кэши результатов, ответов наставника, счётчики лимитов наставника и песочницы | Память процесса | нет | кэш и счётчики начинаются заново |

Что из этого следует:

- **Несколько экземпляров без привязки сессий:** загрузка, сделанная на одном экземпляре, не видна другому, обучение и обученная сеть живут на том, где запущены,
  а лимит запросов к наставнику и число запусков в песочнице считаются отдельно на каждом. Пока общего хранилища нет, это нужно обеспечить привязкой сессий.
- **Если диск сервера временный:** базу данных держите в PostgreSQL, а обученные сети и профили LAB+
  считайте пропадающими при смене или перезапуске экземпляра, если не подключён постоянный диск или общее хранилище.
- **Одно обучение на экземпляр:** запуск обучения одним студентом занимает единственный `Trainer` экземпляра; остальные получают ответ, что обучение уже идёт.
  Статус и «Остановить» общие для всех студентов этого экземпляра.
- **Песочница практикума:** число одновременных запусков ограничено настройкой `SANDBOX_MAX_CONCURRENT`; при перегрузке студент получает ответ
  «Сервер занят, повторите» (код 503), и попытка не засчитывается. Лимит памяти на запуск работает только на Linux и macOS, на Windows его нет.

## Нагрузочный тест

Для 20–30 одновременных студентов: `scripts/loadtest/locustfile.py` (Locust ставится отдельно: `pip install -r scripts/loadtest/requirements.txt`). Запускать только против локального сервера. Измерение на Windows (30 пользователей, 90 с, SQLite, наставник по правилам): 1006 запросов, ошибок 0; медиана 370 мс, 95-й процентиль 4,4 с. Самые медленные: первое чтение списка образцов лиц (около 8 с, пока сканируется галерея LFW) и запуск кода в песочнице (в среднем 2,6 с).
